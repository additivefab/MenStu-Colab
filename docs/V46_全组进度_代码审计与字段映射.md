## 2. 权限和并发权威入口

| 目标 | 当前权威实现 | V46 处理方式 |
|---|---|---|
| 学生可见范围 | `lib/authorization.ts#getStudentScope`、`scopeSql` | 总览 API 先取 scope，再查询学生及摘要；空分配 admin 返回 0 人 |
| 学生查看权限 | `canViewStudent` | 总览不新增旁路；深链接进入既有学生档案后再次校验 |
| 正式审核权限 | `canReviewStudent` | 只用于判断是否生成导师可处理 issue；写操作仍由原端点复核 |
| 进展自审禁止 | `app/api/reviews/route.ts` 比较 `submitted_by_user_id` | 总览不会为本人提交/代录的记录生成可执行审核动作 |
| 方案自审禁止 | `app/api/proposals/route.ts` 比较最新版本提交人 | 总览只在非本人提交且有 `can_review` 时生成方案审核动作 |
| 审核租约 | `app/api/reviews/route.ts` 的 30 分钟领取/释放/超时重领 | 总览只读取租约事实；不创建或修改租约 |
| 并发冲突 | 审核、方案和指导端点的条件更新与 409 | 总览只深链接到权威入口，不复制 mutation，不乐观伪造成功 |

## 3. 数据字段映射

| 总览语义 | 真实表/字段 | 权威选择规则 |
|---|---|---|
| 学生身份摘要 | `students.id/display_name/degree/grade_year/stage/current_focus/cadence_days` | 仅活动学生，且必须先经过当前用户 scope |
| 正式跟踪起点 | `students.tracking_started_at` | 字段为空时不得以创建、分配或草稿时间代替 |
| 最近可信进展 | `progress_entries` + 当前 `progress_revisions` | 父记录和当前修订同时为 `accepted`，assessment/status 为 `substantive`；只使用导师审核确认时间，缺失时不得回退到创建/提交时间 |
| 最近有效提交 | `progress_entries` + 当前 `progress_revisions` | 当前修订存在且非 rejected；与可信进展时间分开 |
| 待导师进展审核 | `progress_entries.review_status`、提交人、审核人、`review_claimed_at` | 只在有 `can_review`、非自审且租约可用/归本人/已超时的情况下成为导师动作 |
| 待学生补交 | `progress_entries.review_status = changes_requested` | 作为“等学生”，不推进可信进展 |
| 论文位置 | `student_papers` | 优先 active，其次 on_hold；仅返回题目、阶段和状态摘要 |
| 当前论文下一步 | `paper_progress_details` | 只从当前修订已接受且论文仍为 `active/on_hold` 的进展中选取；关闭论文的已接受/待补交事实均不复活 |
| 当前课题下一步 | `project_progress_details` | 未关联节点的合法课题进展仍有效；一旦关联节点，必须匹配当前已确认方案版本及未归档、未完成节点，旧版本或已归档/完成事实不复活 |
| 方案审核 | `research_proposals` + 最新 `research_proposal_versions` | submitted、当前导师有审核权且不是最新版本提交人 |
| 当前培养节点 | `research_milestones` + approved proposal | 仅未归档、未完成节点；blocked 和逾期是硬问题 |
| 开放指导 | `student_guidance_notes` | 等学生、学生已提交待导师验收、下一行动逾期分别生成对应 issue |

## 4. 已确认的旧实现风险

1. `app/api/dashboard/route.ts` 为深层工作台一次读取进展、修订、审计、附件等，并对进展使用全局 `LIMIT 1000`；它不适合作为全组摘要来源。
2. 旧课题组页面使用 `riskFromDate(last_substantive_at ?? tracking_started_at)`；缺少日期时会得到“红色 999 天”，不能复用于 V46。
3. 旧前端会在已返回的历史数组上计算最近提交和节奏；V46 必须改为数据库侧按学生选取权威摘要。
4. 当前 `dashboard.tsx` 已超过 3000 行；V46 只接入新视图，规则、查询和主要 UI 均拆到独立模块。

## 5. V46 架构裁决

- `lib/dashboard-overview/types.ts`：API 契约、issue 与 action 枚举。
- `lib/dashboard-overview/dates.ts`：Asia/Shanghai 自然日工具。
- `lib/dashboard-overview/derive.ts`：唯一状态推导纯函数；不读取数据库、React 或全局当前时间。
- `lib/dashboard-overview/query.ts`：固定数量的 scope 内批量摘要查询；不做逐生查询。
- `lib/dashboard-overview/assemble.ts`：将查询事实、当前查看者权限与单一状态规则组装为完整响应；无 Cloudflare/React 依赖，可直接执行权限矩阵与 100 人契约测试。
- `app/api/dashboard/overview/route.ts`：身份、scope、查询、互斥计数和 `private, no-store` 响应。
- `lib/dashboard-overview/contract.ts`：响应字段白名单、敏感/深层字段递归禁入、计数与主 issue 一致性、100 人与 250 KB 门禁。
- `components/dashboard-overview/*`：URL 状态、计数筛选、紧凑表/移动摘要和右侧详情栏。

## 6. 状态优先级

```text
需立即介入 intervene
  > 等我处理 mentor
  > 等学生 student
  > 正常推进 on_track
  > 信息不足 insufficient
```

- cadence 超期本身不进入红色；无更高优先事项时进入“等学生”。
- 普通未到期下一行动属于“正常推进”。
- 所有事实保留在 `issues[]`，主状态取稳定排序后的第一项。
- AI 候选、待审核、退回记录只可以更新最近提交时间，不能更新可信进展时间。
- 截止日当天不逾期；次日 00:00（Asia/Shanghai）起算逾期。
