# 页面切换性能优化（2026-10-23）

## 问题与改动

用户反馈切换学生、论文、任务页面慢。学生档案原先读取全组 dashboard 和全部研究方案，然后在浏览器中过滤当前学生；四个接口全部完成前不展示档案。全组工作台还等待无关的预约接口。

本次改动：

- dashboard / proposals GET 支持 studentId，数据库查询前在原账号权限范围内收窄。默认全组响应契约保持，拒绝越权和无效参数。
- 学生档案改用单学生查询；核心进展与方案就绪即可展示，指导和成果分别显示加载状态及错误；中止旧请求，切换学生重置组件。
- 工作台核心数据不再等待预约响应；保存操作仍等待同步完成。刷新保留现有页面，失败可重试，防止错误后的无限自动请求。
- 总览在页签间保持组件状态，返回时后台刷新；学生任务页首次打开后保留，切回无需重新请求，写入事件仍触发刷新。
- 进展明细按 Map 分组，替代反复扫描；方案审核权限一次查询，保留自审限制。
- 修复历史进展超过 D1 绑定参数上限造成的 500：每 90 个进展 ID 分块，四类明细各自用一次 D1 batch 读取；保持全局最新 1000 条进展限制和每条历史顺序。
- 浏览器验收发现当前 Vinext 的 Link 动态导航导出缺失，点击和预取报错。保留原生跨页链接，并修复学生页原有的返回/管理方案 Link；不升级框架。首页内侧栏和页签仍在本页切换。

## 性能对照

独立 Miniflare 内存 D1，26 名合成学生，每条进展有 3 个版本；每人 2 篇论文、1 个方案（3 个版本）。12 次交错测量、各 2 次预热。比较同一新构建的全组请求（旧页面读取范围）和单学生请求，不是生产网络测速或 V66/V67 版本 A/B。

| 合成数据 | 全组 dashboard 响应 | 单学生响应 | 缩减 | 本地 warm HTTP 中位数 |
|---|---:|---:|---:|---:|
| 26 × 3 条进展 | 1,183,031 B | 45,881 B | 96.1% | 14.2 → 4.9 ms |
| 26 × 20 条进展 | 6,174,158 B | 237,656 B | 96.2% | 58.9 → 6.9 ms |

方案响应同样由 168,830 B 降到 6,500 B。真实响应节省取决于当前学生与全组记录占比。

修复分块前，520 条进展的全组请求实际返回 SQL 参数过多的 500，因此不存在这一规模的合法旧版耗时对照。

复现实验脚本、原始结果及请求日志保存在本机 ignored 的 `outputs/performance-2026-10-23/`；不随生产包部署。完整范围/大数据量回归保存在 `tests/student-scoped-reads-worker.test.mjs`。

## 验证

- 生产构建通过，274 项自动化测试全部通过。
- 新 HTTP/D1 回归覆盖账号范围、导师只读与审核权限、自审限制、双身份、无效参数、嵌套明细完整性；520 条进展正常，1120 条仍按最新 1000 条截断。
- TypeScript 检查通过；本次修改文件的定向 ESLint 检查通过。未宣称全仓历史 Lint 问题全部消除。
- 本地浏览器使用合成账号，核验学生01/02切换、论文/任务切换、返回列表及方案深链接。任务页往返后服务日志仍只有一次整页任务请求。

不调整数据库 schema、密码、角色、学生记录、飞书配置或站点访问范围。未使用真实学生任务做演示，未发送群消息。

## 仍需关注

跨学生档案仍为原生网页导航，以规避当前框架产物错误；跨页返回仍需重新请求授权数据。真实校园网、家庭宽带、移动网络及生产登录后的端到端耗时，本次未做全面测量。生产就绪探针的双管理员统计、备份恢复等 v0.8 待办不在本次性能修改范围。
