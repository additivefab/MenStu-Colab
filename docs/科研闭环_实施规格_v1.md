# 科研闭环实施规格 v1

日期：2026-11-03。分支：`feature/research-loop`。

本规格是并行开发的唯一契约，依据：

- 用户提供的设计包 `research_collaboration_design_pack_20261103/`（架构契约、Codex GOAL、验收矩阵 T01–T26）；
- 用户确认的五项决定；
- 当前源码。

设计包中凡是“建议”的内容，本规格给出具体落地方式；凡是本规格没有规定的，以设计包为准。

## 1. 已确定的决定

| 编号 | 决定 | 落地方式 |
|---|---|---|
| D1 | 保持飞书登录 | 不改登录。GitHub 身份沿用现有 `student_repository_bindings.github_username` |
| D2 | GitHub Team | 运行审批（G3）在平台侧实施；Environments required reviewers 不可用于私有仓库，不依赖。分支保护由仓库管理员配置 |
| D3 | 使用订阅 | 代理在实验室代理工作进程（agent worker）上运行，使用每人自己的订阅凭据：Codex 用 ChatGPT 登录缓存（每个凭据档案一个 `CODEX_HOME`，同档案串行），Claude 用本人的 `CLAUDE_CODE_OAUTH_TOKEN`。平台只保存“用户 ↔ 凭据档案 ID ↔ 工作进程”的映射，不保存任何凭据 |
| D4 | 实验室服务器 | 计算执行器部署在实验室服务器上，主动向平台领取任务，不开放入站端口。不把生产 GPU 主机注册为 GitHub runner |
| D5 | 数据可调用、不可拷贝 | 作业只读挂载数据、禁止联网。输出经外发闸门处理：默认扣留，只自动外发通过 `tanyan.metrics/v1` 校验的 `metrics.json`；其他路径须由数据持有方在外发策略中登记（第 7 批，R03）。已登记的文件仍受扩展名白名单、大小上限、图片默认不外发等限制；符号链接、越界路径和哈希命中数据集清单的文件一律拒绝。代理和学生不能访问原始数据；平台、R2、GitHub 和云端模型都只接收派生结果 |

提供商顺序：按设计包，Codex 是第一提供商，闭环跑通后再接 Claude。适配器契约从一开始就同时覆盖两者，DeepSeek 保留在枚举中，本期不实现。

## 5. 鉴权规则

- 用户接口：`requireAppUser` + 写操作 `assertSameOrigin` + `canViewStudent`（查看）/ `canReviewStudent`（审核），返回 `Cache-Control: private, no-store`，错误信息用中文，风格与 `app/api/student-repositories/route.ts` 一致。
- 学生只能操作本人记录。导师只能操作分配范围内的学生，审核类操作要求 `can_review=1`。超级管理员可以操作全部学生。
- 不能自我批准：G3 批准人不能是 RunSpec 的创建人（超级管理员也不例外，对应现有“不能审核自己提交的进展”规则）。G2 额外审查由导师或超级管理员执行。
- 撤权（T12）：学生停用、导师分配撤销、数据授权撤销、批准撤销后，claim 不再派发新工作；进行中的工作在下一次心跳时返回 `cancelRequested: true`，并写入审计。
- 实验室接口：`authenticateLabRunner(d1, request, "compute" | "agent")`，与用户会话完全分离。

## 6. 接口

所有接口沿用仓库风格：单一路由文件，读用查询参数，写用 JSON body 加 `action` 字段，不使用动态路由段。

### 6.1 研究任务与代理（W3）

- `GET /api/research-tasks?studentId=` 返回列表；`?taskId=` 返回详情，包括版本、事件、attempts、change requests 摘要。
- `POST /api/research-tasks`，按 `action` 区分：
  - `create`：`studentId, mutationId, sourceGuidanceNoteId?` + 内容字段；
  - `revise`：`taskId, expectedVersion` + 内容字段，生成新版本并把状态置回 draft；
  - `confirm`：`taskId, version`，学生本人或可审核导师都可以确认；
  - `close` / `cancel`：`taskId`。
- `GET /api/agent-attempts?taskId=` 或 `?attemptId=&afterSequence=`。
- `POST /api/agent-attempts`：
  - `start`：`taskId, provider, idempotencyKey, baseRef?`。要求任务已确认、学生有 active 的 `repository_links`、发起人对该 provider 有 active 凭据档案。基准 SHA 用 `resolveCommitSha` 解析（默认分支）。快照取已确认版本。
  - `cancel`：`attemptId`。
- `GET` / `POST /api/admin/agent-credential-profiles`（超级管理员）：`create {userId, provider, workerId}`、`deactivate {id}`。
- `POST /api/lab/agent-attempts`（worker 鉴权），按 contracts 中的 `claim` / `heartbeat` / `events` / `result` 实现：
  - claim 只派发 `credential_profiles.worker_id` 等于本 worker 的排队任务，按创建时间先后；每次领取 `lease_epoch + 1`。
  - result 先用 `evaluatePathPolicy` 复核路径：超出允许范围的改动整体拒绝（attempt 置为 failed，`errorCode=POLICY_VIOLATION`，T04）；触及受保护路径则 `requires_extra_review=1`（T05）。
  - 文件和 diff 按大小上限检查，变更内容以 JSON 存到 R2 键 `agent-attempts/<attemptId>/change.json`，结构为 `{files, unifiedDiff}`。
  - 然后创建 `change_requests`，状态 `pending_review`，分支名 `tanyan/<taskId 后 8 位>/<attemptId 后 8 位>`。
- 租约过期：running 状态的 attempt 租约过期后置为 failed（`LEASE_EXPIRED`），不自动重派。代理任务重做成本低，由用户新建 attempt，避免重复执行。

### 6.2 GitHub（W2）

- 配置（Worker secrets）：`GITHUB_APP_ID`、`GITHUB_APP_PRIVATE_KEY`（PKCS#8 PEM）、`GITHUB_WEBHOOK_SECRET`。JWT 用 RS256，经 WebCrypto 签名。
- 实现 `mintRepositoryReadToken`：限定单仓库、`contents:read`。实现 `resolveCommitSha`。
- 发布服务 `publishChangeRequest`：
  - 读取 change request 和 R2 中的变更；
  - mint 单仓库 token，权限为 `contents:write` + `pull_requests:write`；
  - 基于 base SHA 的 tree 创建 blobs、tree、commit，提交说明带 `Tanyan-Task:`、`Tanyan-Attempt:` 和 `Assisted-by: <provider>:<model>`；
  - 建分支 ref，开 Draft PR，正文带 `<!-- tanyan:origin=platform -->`；
  - 幂等：已存在的 ref 或 PR 会被识别并复用；
  - `requires_extra_review=1` 时，必须先由导师或超级管理员执行 `approve_extra_review`。
- `GET /api/change-requests?taskId=` 或 `?changeRequestId=`；`POST /api/change-requests`：`publish` / `approve_extra_review` / `reject`，使用 `expectedVersion` 做 CAS。
- `POST /api/github/webhook`：
  - 用原始 body 验证 `X-Hub-Signature-256`（常量时间比较），失败返回 401（T07）；
  - 以 delivery ID 为主键，重复投递返回 200 且不产生副作用（T06）；
  - 处理 `installation` / `installation_repositories`（撤销对应链接）/ `pull_request`（更新 change request 状态和 head SHA）；
  - 带平台标记或由本 App 发送的事件记为 `platform_echo`，忽略（T08）；
  - 安装 ID 或仓库 ID 与记录不符的事件隔离为 ignored，不进入任何队列；
  - 摘要只存必要字段，不存全文。
- `GET` / `POST /api/admin/github`（超级管理员）：`sync_installations`；`link_repository {studentId}`，按学生已有绑定的 full name 在安装范围内解析出稳定 ID 和默认分支，写入 `repository_links`；`revoke_link {studentId}`。

### 6.3 运行登记（W4）

- `GET` / `POST /api/admin/lab`（超级管理员）：
  - `register_runner {label, kind}` 只返回一次 token；`disable_runner`；
  - `register_entrypoint {studentId, name, argv[], paramsSchema, imageRef, evaluationProtocolSha256}`，`imageRef` 必须带 `@sha256:` 摘要，argv 是数组、不经 shell；
  - `register_dataset {label, runnerId, manifestSha256, splitManifestSha256, egressPolicy}`；
  - `grant_dataset` / `revoke_dataset {datasetVersionId, studentId}`。
- `POST /api/runs`，按 `action` 区分：
  - `create {taskId, changeRequestId | executedCommitSha, entrypointId, params, datasetVersionId, resources, idempotencyKey}`：
    - 任务须已确认；入口须属于该学生仓库；数据授权须 active；资源不得超过任务预算；
    - 有 changeRequestId 时用其 head SHA；直接给 SHA 时用 `resolveCommitSha` 校验（未配置 GitHub App 时返回 503）；
    - 生成 RunSpec（egress 取自数据集策略，评价协议取自入口）→ 写入 `run_specs` → 新建 run（`attempt = max + 1`，状态 `awaiting_approval`，`submit_tag = tanyan-<runId>`）。
  - `approve {runId, runSpecSha256}`：客户端回传它审阅过的哈希，不一致时拒绝（T09/T10）；批准人不能是创建人。
  - `revoke_approval`。
  - `cancel`：awaiting_approval 和 queued 直接置为 canceled，其他进行中状态置为 cancel_requested。
  - `rerun`：新建一行 run，同一规范，需要重新批准（T23）。
- `GET /api/runs?taskId=` 或 `?runId=`：详情包括规范、批准、事件、产物、结果、评审和评论。`GET /api/run-artifacts?artifactId=` 只提供 `published` 的产物，按学生范围鉴权（T01）。
- `POST /api/run-results`：
  - `review {runId, expectedVersion, state, hypothesisOutcome, note}`：technical_validity 不是 valid 时不允许 accepted（T19）；
  - `comment {runId, requestId, body, parentCommentId?}`；
  - `followup {runId, mutationId, ...内容}`：调用 `createResearchTask`，`sourceRunId` 设为本 run、`parentTaskId` 设为本 run 的任务，并回写 `followup_task_id`（T25）。
- `POST /api/lab/runs`（compute 鉴权），按 contracts 实现：
  - claim：先处理本执行器名下租约过期或处于 reconciling 的 run，以 reconcile 模式返回（不重新提交，T11）；否则按入队时间先后，派发本执行器托管数据集上、批准有效、授权有效、学生 active 的 queued run，状态改为 dispatching，`lease_epoch + 1`。`mintRepositoryReadToken` 抛出未配置错误时 `repository: null`。
  - heartbeat：校验租约后续期，允许 dispatching→running→collecting，并返回 `cancelRequested`。
  - reconcile：
    - 找到作业：pending 或 running → running；finished → collecting；failed 或 canceled → 对应终态；
    - 没找到：已请求取消 → canceled；否则 → dispatching，由执行器重新提交。
  - complete：
    - 逐项核对 manifest 与 spec（runId、attempt、spec 哈希、approvalId、执行 SHA、数据哈希、评价协议）；
    - 平台按 egress 策略复核每个产物，只能把 published 降级为 held，不能升级；`publishedFiles` 的 sha256 必须与 manifest 一致，才写入 R2 键 `runs/<runId>/<relativePath>`；
    - metrics 必须来自 published 的 metrics 产物，通过 `validateMetricsFile`，且评价协议哈希与规范一致；
    - technical_validity：outcome 为 completed、exitCode 为 0、metrics 有效 → valid；metrics 无效 → invalid；没有 metrics → unknown；
    - 写入 `run_results` 和 `result_reviews(pending)`。
- 所有状态变化都写入 `run_events`（sequence 单调递增），并用 `canTransition(RUN_TRANSITIONS, …)` 校验。

## 7. 实验室进程

### 7.1 计算执行器 `infra/lab-runner/`（W5）

- 部署形态：实验室服务器上的 Node 22+ 守护进程，配置文件为 JSON，token 来自环境变量或文件，不放进配置。
- 主循环：claim → execute 或 reconcile → heartbeat（每 30 秒）→ complete。本地状态文件按 run 目录持久化，重启后可以恢复。
- 执行步骤：
  1. 校验数据集清单文件的 sha256 等于 `spec.dataset.manifestSha256`；
  2. 按 SHA 检出代码到 `work/<runId>/src`：`git fetch` 指定 SHA → `checkout` → 校验 HEAD → 清除凭据；
  3. 输出目录为 `work/<runId>/out`；
  4. 调度适配器 `local` / `slurm` 以 `submitTag` 命名作业：Slurm 用 `sbatch --parsable --job-name=<tag>`，对账用 `squeue` / `sacct` 按名称查询，取消用 `scancel`；
  5. 作业在 Apptainer 中运行：`--containall --cleanenv --no-home`，网络关闭，数据只读挂载，代码只读，只有 out 可写，按资源限制运行。具体参数以 Apptainer 官方文档为准，并写成可配置项。
- 外发闸门（D5）：
  - 遍历 out 时用 lstat：符号链接、特殊文件、越界路径一律 rejected；
  - 扩展名不在白名单 → held；图片且 `allowImages=false` → held；超过单文件或总量上限 → held；sha256 命中数据集清单 → rejected；
  - 只有 published 且不超过 `LIMITS.maxPublishedArtifactBytes` 的文件，才随 complete 内联上传；
  - held 的文件留在实验室存储，只回传 locator。
- metrics 只读取入口约定的 `out/metrics.json`，执行器先做 schema 校验再上报，平台会再校验一次。

### 7.2 代理工作进程 `infra/agent-worker/`（W6）

- 主循环：claim → 在 `work/<attemptId>` 检出 base SHA → 用任务快照构造提示 → 适配器运行（流式事件经脱敏、截断后上报；heartbeat 返回取消时调用适配器 cancel）→ 收集变更（`git diff` 与 base 比较，得到 files 和 unifiedDiff）→ 本地先跑一遍路径策略 → 提交 result。
- 适配器实现设计包 §4 的 `AgentAdapter`：`capabilities` / `start` / `streamEvents` / `cancel` / `resume`（不支持就明确返回 unsupported）/ `collectChanges` / `usage`。
  - **Codex**：`@openai/codex-sdk`，依赖装在 `infra/agent-worker/package.json`，不进平台 bundle；`CODEX_HOME=profiles/<credentialProfileId>/codex`；sandbox 用 workspace-write。
  - **Claude**：调用 `claude -p`，流式 JSON 输出，工具白名单，`CLAUDE_CODE_OAUTH_TOKEN` 从档案文件读取。
  - 同一凭据档案用文件锁串行执行。
- 代理进程拿不到任何 GitHub 写凭据、数据路径或其他档案的凭据。仓库里的 README、AGENTS.md 只是任务材料，不能扩大权限（T14）。

## 9. 测试与交付要求（所有工作流）

- Worker 接口测试沿用 `tests/*-worker.test.mjs` 模式：Miniflare 加载 `dist/server` 构建产物，`applyD1Migrations`，通过 `outboundService` 拦截全部外部请求。外部 GitHub 调用使用 fetch 替身，并明确标注“模拟”。
- 每条验收 ID 要么有对应测试，要么在报告里写明为什么无法在本地执行（例如真实 GPU、真实 GitHub）。不得把模拟测试说成真实集成。
- 交付前运行：`npm run typecheck`、`npm run lint`（不得新增错误）、`npm test`（全量通过）。
- 每个工作流在自己的分支提交，提交信息说明范围，不推送远端。
- 设计包的约束全部适用：

## 13. 第 6、7 批契约与失败语义（schema 28）

- **迁移 0028：** 新增 `change_requests.published_at`。运行时确认该列存在后，才把版本从 27 升到 28。
- **首期协作范围（第二次评估 G05）：**
  - 每个研究任务归属一名学生；导师按分配范围审核；同伴只能通过“代码审查委托”参与，范围见第 12 节。
  - 本期不做“多人共同读写同一课题”。需要时另加显式的项目成员角色和撤权矩阵，不能靠放宽 `canViewStudent` 实现。
- **预算措辞（G04）：** `TaskBudget` 只限制代理分钟、GPU 数、运行时长和正式评测次数。代理用量（tokens）只记录，不做硬上限；界面和文档不得宣称限制了费用。真实的资源仲裁以 Slurm / cgroups 为准。
- **设计包模板（G06）：** `research_collaboration_design_pack_20261103/templates/` 是概念示例，不能直接交给执行器。可执行契约以 `lib/research-loop/contracts.ts` 的 `tanyan.task/v1`、`tanyan.runspec/v1`、`tanyan.manifest/v1`、`tanyan.metrics/v1` 为准。
- **失败语义（第 7 批，R01–R05）：**
  - **代理结果：** 工作进程先把结果原子写入本地 outbox，再发送；只有得到平台的明确答复后，才删除 outbox 条目和工作区。租约已转移（409 `LEASE_LOST`）时丢弃，不重发。
  - **提交结果未知：** 执行器不得立即重新提交。它在有限时间内按 `submitTag` 对账：找到作业就接管；仍找不到就以明确原因结束，交给人决定是否重跑。
  - **输入数据：** 批准绑定的是数据的实际字节。执行器在提交前逐文件校验，或校验不可变快照的封签，并把 `inputs.dataDigest` / `dataVerification` 写入运行清单。
  - **运行环境：** 执行器校验本地 SIF 文件的 sha256，并把 `environment.imageFileSha256` / `imageSource` 写入运行清单。
  - **外发：** 默认扣留，只有通过 `tanyan.metrics/v1` 校验的 `metrics.json` 自动外发。其他路径需要数据持有方在数据集外发策略中明确授权。内容扫描只是辅助手段，不构成“不可拷贝”的保证。
  - **Git 元数据：** 收集改动前恢复可信 Git 状态时，不跟随符号链接，也不写入工作区之外。
