# 月度提交与后续工作

## 业务行为

学生的本月提交与后续工作分别跟踪。总览、总览抽屉、学生首页与进展页、导师审核区增加三阶段条：本月准备 → 本月已提交 → 本月已确认。只有明确退回或未通过的本月材料显示“本月待补充”，使用琥珀色。阶段条表示提交与确认过程，不表示科研完成百分比。

导师审核以“确认本次进展”为主操作，“本次材料不完整，退回补充”为次要操作。待办数量改用蓝灰色；审核后显示持续回执，标明学生、记录、修订和结果，避免自动选择下一条待办后被误认为原审核仍未处理。

确认后的回执可直接“安排后续工作”，关联已确认进展。期限不自动填入，也不自动安排到下个月，由导师每次选择。后续工作复用既有指导任务及验收流程；原进展的审核结果不变，未解决问题也不会被自动关闭。学生仍可提交下一次进展。

## 统计口径与权限

- 使用上海时区的当前自然月，依据修订提交时间，不依据导师审核时间。没有新增“成果所属月”字段，不能把补录记录推断成另一月份。
- 同一条进展本月的多个修订仅统计最后一个。存在待补充时显示待补充；否则有待确认时显示已提交；全数确认后显示已确认；无正式提交时显示准备中。
- 未确认的 AI 导入纪要作为候选独立展示；学生亲自提交修订或导师确认后，按对应提交月份进入统计。
- 专用 SQL 按授权学生汇总计数，不受仪表盘正文列表 1000 条上限影响，不读取额外进展正文。每批最多 90 名学生、93 个绑定参数。
- 活跃学生、软删除、导师授权范围和学生隔离沿用既有约束。正式进展后续任务只可关联同一学生、未删除且已确认的来源；旧 AI 纪要关联规则兼容保留。
- 审核请求携带页面看到的修订号，服务器校验并纳入原子更新条件，防止旧页面误审核新修订。
- 原有实际节点、下一行动期限和节奏风险继续单独展示，不改变月度提交阶段。旧问题不阻止新提交的 V69 规则保留。

没有数据库迁移、生产学生数据改写、飞书消息发送或访问受众变更。
