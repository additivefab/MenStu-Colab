# 全组问题记录与阻塞展示

## 用户需求

增加全组统一的“问题记录”列表；普通阻塞无需让审核端自动标红。承接当天 V67 的页面切换性能优化。

## 已实现

- 主导航新增“问题记录”，入口 `/?mentorView=issues`。支持学生、来源、状态和关键词组合筛选，每页最多 30 条；搜索与筛选保留在 URL。
- `GET /api/problem-records` 聚合当前已确认进展中的困难、已有困难处理历史、有效方案的受阻节点，以及问题类型的指导记录。与原处理记录共用状态，不创建第二份困难事实。
- “记录问题”复用日常指导数据和审计流程，标题及情况说明必填，跟进安排和日期可选。原记录可继续确认完成，完成后仍在“已解决”列表保留。
- 历史未完成单列为“历史记录”，保留原状态，不把被新版本替换等同于已解决。进展链接携带 revision，精确定位旧版本；历史事项不自动打开编辑器。
- 总览增加蓝灰色“待跟进”状态。普通困难和受阻节点不再直接归入“需立即介入”；审核事实和方案节点采用中性颜色。独立的节点逾期、下一行动逾期及进展节奏风险仍按原规则提醒。

## 权限与性能

接口沿用导师分配范围：超级管理员查看全组，导师仅查看授权学生，学生端不能读取全组列表。创建问题遵循日常指导权限（无需正式审核权，但不可对本人档案下达指导）。所有返回均 `private, no-store`、`Vary: Cookie`。

学生 ID 每批最多 90 个，四类来源按批读取，无逐学生查询；列表不加载附件及完整审计事件。直接进入问题页只需登录摘要和问题接口，不触发全组 dashboard。组件返回时保留已有结果并刷新，隐藏时取消未完成请求。跨学生档案继续使用 V67 的原生导航兼容方案。

## 验证

- 生产构建、TypeScript、改动文件定向 ESLint 通过。进展面板原有两处 `set-state-in-effect` Lint 错误仍存在，经与 HEAD 对照确认本次未新增；不宣称全仓 Lint 已清零。
- 285 项自动化测试全部通过，覆盖三来源聚合、去重、旧状态保留、授权隔离、186 人分块、普通问题非红、受阻并逾期、精准历史定位。
- 本地 Miniflare 内存 D1 / R2 与合成账号验证：总览跳按学生筛选的问题页；搜索后切状态仍保留关键词；历史版本定位；无跟进日期保存问题；原档案确认完成；返回后进入已解决列表。浏览器无 error 级控制台日志。
- 本地日志 `outputs/problem-records-2026-10-23/qa-requests.jsonl` 确认直接进入问题页未请求全组 `/api/dashboard`。合成 26 人、132 条问题的摘要响应为 73,303 B；这是本地样本大小，不是生产延迟承诺。

## 边界与回退

没有 schema 变更、生产业务数据迁移、账号或飞书配置变更。测试记录只写入隔离的本地内存数据库。尚未形成独立处理记录、且已经被后续版本替代的旧困难，仍保留在原始进展历史，不自动批量迁入本列表。已解除受阻的节点仍以原方案审计为准，不新增节点问题历史表。

普通问题仍可在原协调事项中查看；本次调整不删除审核事项。生产发布信息记在外层 `docs/项目交接文档_v0.10.md`。必要时可回退已保存的 V67，无需数据库回滚。
