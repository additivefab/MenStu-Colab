# 学生独立登录与原账号关联

本次增加独立账号和密码登录，适用于已离开原飞书组织、但在系统中已有学生账号的成员。

## 开通与使用

1. 超级管理员使用现有飞书登录，进入「系统管理 → 账号与登录管理」。
2. 在原学生账号下核对账号 ID、绑定学生和本人身份，点击「开通独立登录」。已有密码需要重置时，点击「重新生成密码设置链接」。
3. 将系统显示的账号与一次性链接单独交给学生本人。链接有效期 24 小时，只显示在本次操作结果中；新链接立即取代旧链接和旧密码，并退出该账号已有会话。
4. 学生打开链接，自行设置 15–128 字符密码，再返回网站首页，用显示的拼音缩写账号（如温浩钰 `why`、曹琛 `cc`）和密码登录。不设置统一的 `123456789` 初始密码。
5. 登录后进入「我的账号 → 修改登录密码」，输入原密码和两次新密码。修改成功后所有设备退出，使用新密码重新登录。
6. 忘记密码由超级管理员重新生成设置链接；「停用独立登录」撤销独立密码和未使用链接，并退出该账号已有会话。

当前 26 人名册的登录名已按原学生 ID 固定映射；英文多词姓名取首字母，单词姓名保留原拼写。当前没有重名，重复缩写规则支持追加数字。详见 [学生独立登录账号表](学生独立登录账号表_2026-09-20.md)。后续新增学生应在登录名映射中补充缩写；未配置时使用学生 ID。已有自定义登录名保持不变，旧版学生 ID 登录名在管理员重新生成链接时切换为缩写，界面始终显示实际登录名。

账号和学生数据不会复制。独立凭据直接引用原 app_users.id 和 students.id，原飞书 Open ID、进展、附件、审核人和提交人记录保留。学生只能使用原账号所属档案。此轮开通仅支持已经绑定档案的有效 student 账号，不支持管理员、待授权、停用或尚未建立原账号的学生；不会按姓名自动绑定。

## 实现边界

- 首页默认显示独立登录，飞书登录改为明确选择后启动。
- 使用 Workers 原生 node:crypto scrypt（N=16384、r=8、p=5、随机盐）；不保存明文密码或明文激活令牌。
- 一次性令牌为 256 位随机数，仅保存 SHA-256 摘要。链接使用 URL fragment，页面读取后移除 fragment；提交通过同源 POST，响应禁止缓存。
- 开通、重置、停用仅允许超级管理员；所有操作有追加式审计。学生凭链接设置密码时重新检查原账号与学生绑定，事务内消费链接，防止重放及并发重置。
- 登录按账号和来源 IP 进行持久化频率限制。账号不存在、未激活、停用或密码不匹配使用统一登录错误。
- 自助改密只操作会话所属账号，要求验证原密码，拒绝与原密码相同的新密码；按账号和来源限制尝试次数。改密时再次检查会话、凭据版本和原学生绑定，防止与管理员重置发生竞争，修改后撤销所有旧会话并记录审计。
- 独立会话保留 14 天；每次访问检查凭据版本、原学生绑定和学生角色。角色升为管理员、学生停用、绑定变化、密码重置或独立登录停用后，旧独立会话失效。
- 原飞书登录保留；独立学生登录不要求配置飞书凭据。飞书机器人、会议纪要和提醒仍依赖各自飞书权限，独立登录不自动恢复这些能力。

## 发布与回滚

新增数据库迁移 0022_local_student_login.sql，结构版本为 22。运行时升级也包含同样的新表和会话列；部署环境应按现有流程应用数据库迁移。升级前保留 D1 备份。

本次只新增凭据、登录限流、审计表与会话来源字段，不改写学生和历史业务记录。旧应用只支持 schema 21，因此数据库升级后不能直接回滚到旧构建；优先前向修复，或使用已验证的数据库备份恢复方案。可以先在管理界面停用独立登录。

验证包括密码与令牌、绑定与角色变化、限流、迁移、完整 Workers HTTP 登录流程和原有回归测试。上线后仍须由管理员为真实学生生成链接，交给本人完成首登验收；测试不代替生产开通。
