# 学生独立登录与原账号关联

本次增加独立账号和密码登录，适用于已离开原飞书组织、但在系统中已有学生账号的成员。

## 开通与使用

1. 按用户 2026-09-20 的明确要求，22 个已核验原账号和学生 ID 绑定的有效普通学生账号统一初始化为密码 `123456789`，用户名为拼音缩写。
2. 学生首次登录后只能打开改密表单，必须验证初始密码并设置 8–128 字符个人密码，不能继续使用统一初始密码，之后重新登录才能查看和提交进展。业务 API 同样强制此限制。改密和密码重设页面的密码框均可点击眼睛图标显示或隐藏输入。
3. 后续进入「我的账号 → 修改登录密码」可再次修改密码。修改成功后所有设备退出，旧密码立即失效。
4. 新学生须先建立并核对原账号绑定。超级管理员进入「系统管理 → 账号与登录管理」，点击「开通独立登录」，同样使用上述初始密码和首次改密流程。
5. 忘记密码由超级管理员重新生成一次性密码设置链接（24 小时有效）；重新生成会撤销旧密码、旧链接和已有会话。「停用独立登录」保留档案和飞书绑定。

名册共有 26 人。佘阳的原账号为超级管理员，继续使用现有登录方式；Muhammad Jalil Ur Rehman、Abbasi、钟昊航尚无原登录账号，本轮不凭姓名自动创建或绑定。其余 22 个原普通学生账号纳入此次初始化。初始化前线上独立凭据表为空。

当前登录名按原学生 ID 固定映射；英文多词姓名取首字母，单词姓名保留原拼写。详见 [学生独立登录账号表](学生独立登录账号表_2026-09-20.md)。后续新增学生应在登录名映射中补充缩写；未配置时使用学生 ID。已有自定义登录名保持不变。

账号和学生数据不会复制。独立凭据直接引用原 app_users.id 和 students.id，原飞书 Open ID、进展、附件、审核人和提交人记录保留。学生只能使用原账号所属档案。此轮开通仅支持已经绑定档案的有效 student 账号，不支持管理员、待授权、停用或尚未建立原账号的学生；不会按姓名自动绑定。

## 实现边界

- 首页默认显示独立登录，飞书登录改为明确选择后启动。
- 使用 Workers 原生 node:crypto scrypt（N=16384、r=8、p=5、随机盐）；不保存明文密码或明文激活令牌。
- 一次性令牌为 256 位随机数，仅保存 SHA-256 摘要。链接使用 URL fragment，页面读取后移除 fragment；提交通过同源 POST，响应禁止缓存。
- 开通、重置、停用仅允许超级管理员；所有操作有追加式审计。学生凭链接设置密码时重新检查原账号与学生绑定，事务内消费链接，防止重放及并发重置。
- 登录按账号和来源 IP 进行持久化频率限制。账号不存在、未激活、停用或密码不匹配使用统一登录错误。
- 自助改密只操作会话所属账号，要求验证原密码，拒绝与原密码相同的新密码；按账号和来源限制尝试次数。改密时再次检查会话、凭据版本和原学生绑定，防止与管理员重置发生竞争，修改后撤销所有旧会话并记录审计。
- 独立会话保留 14 天；每次访问检查凭据版本、原学生绑定和学生角色。角色升为管理员、学生停用、绑定变化、密码重置或独立登录停用后，旧独立会话失效。
- 原飞书登录保留；独立学生登录不要求配置飞书凭据。飞书机器人、会议纪要和提醒仍依赖各自飞书权限，独立登录不自动恢复这些能力。

## 发布与回滚

数据库迁移 0022_local_student_login.sql 增加独立登录；0023_initial_student_password.sql 增加首次改密标记和一次性初始化记录，结构版本为 23。运行时升级也包含同样的新表和会话列；部署环境应按现有流程应用数据库迁移。升级前保留 D1 备份。

一次性初始化与结构迁移分开：服务端在数据库就绪后，按核对过的原账号 ID 与学生 ID 成对匹配创建凭据，并在同一事务写入完成标记；重启或重复请求不会恢复初始密码，也不覆盖已设个人密码或停用凭据。不改写学生和历史业务记录。旧应用只支持 schema 22，因此数据库升级后不能直接回滚到旧构建；优先前向修复，或使用已验证的数据库备份恢复方案。可以先在管理界面停用独立登录。

验证包括密码与令牌、绑定与角色变化、限流、迁移、完整 Workers HTTP 登录流程和原有回归测试。本轮为上述 22 个原学生账号自动开通初始登录；测试使用隔离账号，不替真实学生设置个人密码。
