# 进展与问题独立跟进

## 业务规则

本次提交与未解决问题是两条独立状态。未解决问题不阻止学生提交下一次进展；提交后仍按原流程等待导师确认，确认后若没有其他进度风险，显示“正常推进”。问题继续留在“待解决”列表，提交新进展不会自动关闭它。

- 总览恢复五种进度主状态，另外显示待解决问题数量和入口。普通问题、问题处理结果待确认、问题跟进日期均不单独改变进度主状态；节点期限、下一行动期限和进展节奏仍独立计算。
- 已确认进展中记录的问题按原进展和原修订保留。后续提交、后续修订或论文结束不再让旧问题失去处理入口；仍可提交处理结果、退回补充、确认解决及重新打开。
- 历史问题从所属修订快照读取原文；已有处理记录保留原来源快照、附件和审计。历史修订缺少结构化问题快照且没有处理记录时，不猜测原文，也不套用新版本内容。
- “下一行动”继续按当前课题/论文进展识别，旧下一行动不会因本次调整重新变成当前任务。
- 学生今日页面始终提供记课题进展和记论文进展入口；新增问题字段说明已有问题不必重复填写。

## 实现与权限

`acceptedBlockerSourcesSql` 为问题列表与处理接口提供共享来源集合，按学生分块查询。问题状态复用原 `progress_resolutions`，没有新建第二份问题事实，也没有数据库迁移。

`current` 表示该事项仍可处理；`sourceCurrent` 表示它是否来自同一条进展的当前修订。较早问题修订仍可处理，链接保留修订号；无修订号的旧链接优先选择最新可处理修订。导师待确认队列也保留旧问题的处理结果，而旧下一行动仍受当前来源限制。

学生隔离、导师授权范围、自审限制、删除和停用检查、并发版本保护、请求幂等及附件权限维持原约束。没有修改生产学生数据或发送飞书消息。

## 验证

生产构建、TypeScript 和 300 项自动化回归全部通过。实际编译 Worker 在隔离内存 D1/R2 中验证连续两次提交和确认：旧问题不阻止新提交，新进展待审核时为“等我处理”，确认后为“正常推进”，旧问题仍可独立提交结果并确认解决；同时检查旧下一行动、跨学生访问和确认重试。

本地浏览器使用合成账号验证总览同时显示“正常推进”和“待解决问题”，问题列表可跳到较早修订且仍提供退回与确认按钮，导师待办也准确打开对应修订，控制台没有 error 级日志。截图和测试日志位于 ignored 目录 `outputs/independent-problems-2026-10-23/`。
