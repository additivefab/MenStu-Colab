# V46 导师端全组进度总览：验收与发布说明

## 1. 发布目标

V46 将导师首页从“逐个打开学生档案”升级为“先按权威事实分组，再进入唯一主动作”的全组控制台。新总览与旧“待我处理”“学生”“研究台账”“组会”“课题组”并存；旧页面和原写接口均保留，可独立回滚默认入口。

本次不新增数据库迁移，不改变论文、课题、审核、指导、飞书或身份绑定的既有写入协议。

## 2. 已交付范围

### 2.1 服务端状态与数据

- 单一纯函数生成 `issues[]`、主状态、主原因、下一责任人和主动作。
- 五类互斥状态固定为：`intervene > mentor > student > on_track > insufficient`。
- `latestSubstantiveAt` 只接受“当前修订 + accepted + substantive”的导师确认时间。
- `latestSubmittedAt` 独立取当前修订提交时间；AI 候选、待审核、退回或历史修订不推进可信进展。
- 期限按 `Asia/Shanghai` 自然日计算：截止日当天不逾期，次日 00:00 才逾期。
- cadence 单独超期进入“等学生”，不会进入红色；无跟踪基线进入“信息不足”，不会生成 999 天风险。
- 新增只读 `/api/dashboard/overview`：先做导师范围裁剪，再执行固定数量的数据库聚合；支持 0–100 人，不逐生查询，也不复用旧接口的全局 `LIMIT 1000`。
- 响应只含列表判断所需摘要，不含附件、审计全文、进展全文、Open ID、联系方式或凭证；响应头为 `private, no-store`。

### 2.2 权限与并发边界

- 学生范围继续复用 `getStudentScope` / `scopeSql`。
- `can_review=0` 的导师可查看已分配学生摘要，但不会得到正式审核动作。
- 本人提交不会得到本人审核动作。
- 他人 30 分钟内的有效审核租约不会被抢占；过期租约仍只通过既有审核入口重领。
- 方案审核、指导验收继续复用既有服务端权限；总览没有复制任何写 mutation。
- 前端主动作只由固定 action 枚举映射到已知站内路径，API 返回值不能直接拼接任意 URL。

### 2.3 导师界面

- 新增“全组进度”导航和五类互斥人数卡片，并独立显示“本周可信推进人数”。
- 支持状态、博士/硕士、姓名/方向/论文/节点搜索。
- `state`、`degree`、`q`、`student` 写入 URL；刷新、前进和后退可恢复。
- 默认排序：主状态优先级 → 最早期限 → 最久未有可信进展 → 姓名 → 学生 ID。
- 桌面端为紧凑六列摘要表；窄屏切换为卡片，不依赖横向滚动。
- 每行只有一个主动作；点击摘要打开右侧学生简报，展示全部问题、双轨位置、最近三条可信进展、下一责任人和最早期限。
- 状态同时使用文字、图标和颜色；侧栏具有 dialog 语义、Esc 关闭和关闭后焦点回原行。
- 首次进入总览只加载轻量 session 与 overview 接口；旧深层 dashboard 数据仅在进入旧工作区时加载。

## 4. 发布前后人工检查

### 发布前

- 1440×900：首屏密度、至少 8 行目标、表头和主动作对齐。
- 1280：页面无横向滚动。
- 768 / 390：移动卡片保留状态、原因、下一责任人和主动作。
- 键盘：计数、筛选、学生行和主动作可到达；Enter 打开侧栏；Esc 关闭并回焦。
- URL：刷新、前进、后退恢复筛选和选中学生；非法参数安全回到“全部”。

### 发布后

- 有分配导师：人数、主状态、主动作与实际待办一致。
- 空分配导师：返回 200 和明确空态，不显示全组姓名或计数。
- 超级管理员：可看全组；设置入口仍受原角色控制。
- `can_review=0`、本人提交、他人有效租约：只显示查看入口，不出现可执行审核入口。
- 原“待我处理”、研究台账、组会、学生档案及旧课题组视图可以正常进入。

## 5. 回滚

提交顺序有意拆分：

1. 审计文档。
2. 状态规则与测试。
3. 轻量 API。
4. 总览 UI。
5. 类型基线修复。
6. 验收文档。
7. 默认首页切换（最后一个独立提交）。

若只需恢复旧默认首页，优先 `git revert` 最后一个“默认首页切换”提交；新总览仍可通过 `?view=overview` 使用。若需完全下线，再依次回滚 UI 和 API 提交。数据库没有 V46 migration，因此无需回滚表结构或数据。

## 6. 后续迭代

### P1

- 导师个人置顶、稍后处理和自定义每生 cadence。
- 完成审核后在总览中就地刷新计数，并自动定位下一名导师待办学生。
- 将会议预约中“明确需要导师答复”的事项作为附加 issue，但不改变 P0 主状态规则。
- 增加真实账号的端到端浏览器回归和自动无障碍扫描。

### P2

- 超过 100 人时启用服务端游标分页。
- 导师自定义列、保存筛选视图和可解释趋势。
- 在不泄露正文的前提下增加组级节奏对比与工作量趋势。

P1/P2 不应通过在 React 内新增临时状态判断实现；业务状态仍只能由服务端纯函数统一生成。
