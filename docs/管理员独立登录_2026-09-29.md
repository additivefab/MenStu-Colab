# 管理员独立登录

用户明确要求为佘阳（原账号 #1、student-002、sy）和于兴华（原账号 #24、无学生档案、yxh）开通独立登录。两人均为既有、启用中的超级管理员，使用用户另行指定的密码，不要求首次修改。明文密码不写入源码或文档。

一次性开通按原账号 ID、已核对姓名、超级管理员角色、启用状态、精确学生绑定（可空）匹配，只插入不同盐的密码哈希、授权角色、审计和完成标记。不更改 app_users、学生档案、飞书身份或管理范围。已有凭据、用户名占用、角色或绑定变化时跳过；重复部署不能覆盖新密码、恢复停用凭据或重新开通已删除凭据。

schema 24 允许凭据的 student_id 为空，并增加 authorized_role，旧凭据默认仍授权 student。登录和每次会话读取必须匹配当前数据库角色、学生绑定、凭据版本及启用状态；学生仍须有启用的学生档案。普通学生升为管理员后，其既有密码及会话不能继承管理权限。管理员无需学生档案，不创建占位学生。账号页支持自助改密，超管可对已经明确开通的管理员凭据重置或停用；该入口不自动为其他高权限账号开通密码。

升级时保留所有旧凭据字段和会话。运行时先幂等增加授权角色，再以事务重建可空学生字段，复制原授权角色以避免并发升级覆盖新凭据。迁移文件只修改结构和版本，账号开通另由有持久完成标记的运行时逻辑处理。

上线验证使用用户指定密码登录两人账号，检查管理会话、原账号 ID、无需改密和原管理接口可访问，然后退出验证会话；不替用户修改密码。隔离测试另覆盖数据库升级、并发、角色提升、学生端切换、无档案管理员改密、重置和停用。

数据库升级至 24 后，旧的 schema 23 构建会拒绝继续运行。需要回退时采用前向修复或数据库恢复，不能仅回部署旧构建。
