## 5. 安全边界（已实现的部分）

- 客户端永远不提交仓库 ID；仓库稳定 ID 只能由超级管理员关联。学生修改或解除绑定时，关联会自动撤销。
- 每个 GitHub token 只覆盖一个仓库。代理工作进程只拿到只读 token，PR 由平台的可信发布服务创建；不会写入默认分支，也不会强推。
- 批准绑定 RunSpec 的 sha256，规范中任何字段变化都会使批准失效。不能自我批准，超级管理员也不例外。
- 外发闸门在执行器和平台两侧各检查一次，平台只能把文件降级为不外发，不能升级为外发。哈希命中数据集清单的输出一律拒绝。
- 订阅凭据只存放在代理工作进程所在机器上，平台只保存档案 ID。
- 已知风险：
  - 同一台代理机器上，代理执行的 shell 命令理论上能读到其他人的凭据文件。上线前须为每个任务提供独立容器或虚拟机，或至少用专用用户加文件权限隔离。
  - 原样拷贝能被哈希拦下，但经过重新编码的数据拷贝只能靠扩展名、图片和大小规则拦截。
