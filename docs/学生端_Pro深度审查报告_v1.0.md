## 4. 已实施修改

### 4.1 批次 A：正确性、权威性与恢复

1. 新论文权威边界

   - v19 新增 `paper_submission_candidates`，候选由 `progress_entry_id` 唯一绑定；正式论文晋升后记录 `promoted_paper_id`。
   - 新论文提交不会提前进入 `student_papers`；Dashboard 可显示候选内容，但正式论文列表仍只来自权威台账。
   - 导师 accepted 且 assessment 为 substantive/supporting 时，晋升正式论文、回写候选关联和创建 paper progress detail 在同一批次执行。
   - rejected/changes_requested 不晋升；重复审核由原有审核 CAS 和候选唯一关联共同约束。

2. 幂等与并发

   - progress POST 和 meeting POST 要求 16～128 位稳定 Idempotency-Key；服务端对规范化正文和附件内容计算 SHA-256 请求哈希。
   - 相同 key + 相同内容复用已有结果；相同 key + 不同内容返回 409；数据库部分唯一索引处理并发竞争。
   - 退回补证必须携带 `expectedRevision`；本次修订令牌同时约束候选论文、课题详情、证据、附件和审计事件，防止并发败者污染胜者修订；指导和会议状态更新必须携带 `expectedVersion`，过期标签页返回 409，不静默覆盖。
   - 网络错误时表单内容保留，稳定 key 只在成功后清理。跨刷新保存研究内容到 Web Storage 未实施，因为尚无本地敏感草稿的产品/清理策略；附件也无法由浏览器自动恢复。

3. R2 补偿与可观测清理

   - 在 R2 写入前先持久化 `upload_intent`；Worker 即使在对象写入后硬终止，后续仍能从 D1 找到随机 storage key。
   - 最终 D1 batch 同时写 revision、权威候选/详情、附件元数据并删除 intent；完成前父记录不进入 Dashboard/待审列表。补证时父 CAS 还会核对本次全部 storage key 仍为 `upload_intent`，缺一即不进入最终态。
   - POST 超时恢复先原子删除仍不完整的父记录；PATCH 补偿先原子认领本次整组 intent；后台清理逐对象认领并再次排除已有正式附件。只有认领胜者可以删除 R2，正常最终化、请求补偿和后台回收不能交叉误删。
   - D1 已提交但 SDK/网络返回异常时，POST 会按 user/key/hash/current revision 复查，PATCH 会按 revision + `_operationToken` 复查；确认已提交则返回 replay/success，不删除对象。查询本身失败时返回 503 并保留附件，等待同键重试。
   - 删除失败写入持久队列，保存 progress、student、revision 与失败原因。新鲜上传 intent 有 30 分钟租约，普通补偿失败可立即重试。
   - 新请求会机会式重试队列；readiness 对过期 intent/未清理对象发出 warning，但不返回 storage key。
   - 仍需 Cloudflare R2 故障注入或受控生产演练证明远端真实行为。

4. v19 数据库迁移

   - 新增候选论文表、文件清理队列、progress/meeting 幂等字段与唯一索引、guidance version。
   - fresh 0000→0019 与带旧数据的 v18→v19 均通过；`PRAGMA foreign_key_check` 为空，旧数据与外键语义保留。
   - 回滚注意：v19 数据库不兼容只认识 schema 18 的旧代码。回滚版本必须识别 v19，或在部署前完成可恢复备份；不能直接把旧 V47 二进制当作无条件数据库回滚方案。

### 4.2 批次 B：学生核心闭环

1. 服务端下一步行动引擎

   - 聚合退回补证、逾期指导、阻塞/临期培养节点、论文/课题行动与等待导师上下文。
   - 优先级和同优先级排序稳定；上海自然日同日为“今天到期”，次日才逾期。
   - 只渲染一个主 CTA，同时显示“另有 N 项待办”和等待导师数量。
   - on_hold 论文不产生催办；submitted/in_review 不生成重复提交动作。
   - 多篇活动论文分别进入比较器；未关联培养节点的课题只采用最新权威记录；已完成培养节点不会复活旧行动。常规论文、课题严格排在非临期“新指导待确认”之前。

2. 退回—补证—再审

   - “研究”页收敛为论文/课题权威概览；提交、时间线和退回补证统一进入“进展”页，去除重复的详细 feed。
   - 下一步与时间线均可定位退回项；论文和课题仅在 changes_requested 时显示补证表单。
   - 重提创建新 revision，并提示“Vn 重新提交导师审核”；版本冲突时保留当前输入。

3. 导师指导

   - guidance 增加 version CAS；确认收到、提交完成说明、导师验收和重开均生成不可变事件。
   - 需要导师验收时，学生提交完成说明只进入等待导师状态，不能直接完成。
   - UI 展示指导事件历史；加载失败有明确重试入口。

4. 会议预约

   - 用单条原子 `INSERT ... SELECT ... WHERE` 同时执行有效预约上限与同学生区间重叠判断；区间采用 `[start,end)`，相邻时段允许。
   - POST 幂等，取消/确认/拒绝沿用 version CAS。
   - 创建时原子阻止同一学生自身预约重叠并限制 5 条有效预约；导师确认时再原子检查该导师已经确认的其他学生会议，因此同一导师不能确认两个重叠时段。
   - 当前数据模型仍没有学生提交时的目标导师或外部日历/可用容量，因此不能在“请求创建”阶段承诺某位导师有空，也不能宣称已同步真实日历。

### 4.3 批次 C：信息架构、移动端与可访问性

- 五页职责收敛：下一步负责决策入口；研究负责论文/课题权威概览；进展负责提交、统一时间线与补证；资料负责证据检索；导师负责指导、预约和组会来源。
- 指导/会议错误态增加重试，不只显示失败文案。
- 飞书账户对话框增加 Escape 关闭、焦点锁定、初始焦点和关闭后焦点返回。
- 手机端 time/file 输入字号提升到 16px，补证/指导/重试等关键按钮最小高度 44px。
- Research 的论文选择写入 `paper` 查询参数，刷新、后退和前进可恢复；选中无进展的论文显示本论文空态，不再回退到另一篇论文的数据。
- 指导与会议深链保留具体记录 ID；异步数据未挂载时用受限观察器等待目标出现，成功后再滚动并聚焦，失效目标超时才回退到对应分区。
- 真实键盘、360/390 px 和浏览器后退/前进尚未完成 E2E，当前只能判定为代码与样式层修复。

## 6. 遗留风险与上线门禁

### 6.1 产品迭代版本可发布，但必须带限制条件

- 部署前再次确认保持当前 `public` 访问范围。
- 保存并部署 Sites 新版本后，检查部署状态、生产首页、未登录保护和 readiness；不执行会污染真实学生数据的写烟测。
- 数据库会升级至 v19。必须确认生产 D1 备份/恢复路径，且回滚包兼容 schema 19。
- 本轮无法证明 V47 生产库是否已经存在由旧逻辑提前创建、后来被退回/拒绝的 active/planning 论文。不得用标题或时间启发式自动删除；应先做只读统计，再由导师/管理员逐条确认并形成可审计修复批次。

### 6.2 26 人正式投用仍不通过

- 0/26 正式预绑定；现有 17 个已登录账号映射不是 26 人预绑定完成。
- `/api/health/ready` 当前生产基线 503；需按返回检查项逐项解决。
- 飞书桥接仅能说明进程在运行，不能说明长连接持续健康、事件无丢失或可自动恢复。
- 大陆网络可达性、博士/硕士真实账号隔离、360/390 px 写流程、附件上传/下载、R2 故障补偿、备份恢复、数据导出和回滚演练均缺生产证据。
- Git 仓库没有配置远程；Sites 的源保存可完成本次版本化发布，但不能替代独立 Git 远程备份。
