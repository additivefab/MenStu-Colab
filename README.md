# 探研：科研进展管理系统

面向射线探伤与人工智能课题组的内部管理网站。系统不做学生排名或综合打分，只判断一个阶段内是否产生了可验证的新信息。

## V0.1 已实现

- 25 名匿名演示学生：12 名博士、13 名硕士
- 每人独立设置 7 / 14 / 21 / 30 天更新周期，最长 30 天
- 文献、实验、算法、数据、论文、复现和项目进展提交
- 文献阅读需同时提交可识别论文与阅读结论
- 导师四类审核：实质性进展、支持性工作、需要补充、非进展
- 30 / 60 / 90 天黄、橙、红预警
- 飞书工作台免登、服务端会话、导师/学生权限和账号绑定
- 飞书机器人进展提醒（学生绑定账号后由导师发送）
- 历史记录导入保留为单独授权步骤
- GitHub 私有仓库只保存链接和提交号，完整代码保留给本地模型读取
- D1 持久化数据库与数据库迁移

## 本地运行

需要 Node.js 22.13 或更高版本：

```bash
npm install
npm run dev
```

打开 `http://localhost:3000`。首次请求会在本地 D1 中创建匿名演示数据。

## 验证

```bash
npm run lint
npm test
```

## 真实试用前还需配置

1. 用真实学生名单替换匿名数据，并为每人确认更新周期和当前阶段。
2. 在飞书开放平台创建企业自建应用，添加“网页应用”和“机器人”能力。
3. 网页应用主页填写 `https://tanyan-lab-progress.qwertyuio1230501.chatgpt.site/`。
4. 应用身份权限至少申请“以应用的身份发消息”（`im:message:send_as_bot`）。
5. 第一次发布时只将于兴华老师加入应用可用范围；完成首次登录后再逐步增加学生。
6. 将学生的飞书身份与系统学生记录绑定。
7. 对私有 GitHub 仓库安装只读 GitHub App；网站只接收元数据，本地 Agent 负责读取完整代码。

飞书密钥、GitHub 凭据和其他秘密信息不得写入仓库，应通过部署环境的加密变量配置。

### 飞书身份安全机制

- 飞书客户端通过 `requestAccess` 获取一次性授权码。
- 授权码只传给本系统服务端，服务端与飞书交换用户身份。
- 系统不保存 `user_access_token`，只保存 Open ID、姓名、角色和学生记录映射。
- 登录会话使用随机令牌，数据库只保存令牌的 SHA-256 摘要。
- 所有学生数据接口都在服务端检查角色；学生只能提交和查看自己的数据。
- 首位管理员机制只用于于兴华老师首次登录，完成后必须关闭。
