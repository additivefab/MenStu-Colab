# 探研：科研进展管理系统

面向射线探伤与人工智能课题组的内部管理网站。系统不做学生排名或综合打分，只判断一个阶段内是否产生了可验证的新信息。

方案版本、导师待办、成果台账与证据溯源分别参考了 TUM Thesis
Management、Moodle、OSIRIS、eLabFTW 和 OpenProject 的公开产品模式。
本项目保持独立实现，未复制第三方源码或界面；详情见 `THIRD_PARTY_NOTICES.md`。

## V0.3 已实现

- 26 名真实学生名册：12 名博士、14 名硕士（本地首次启动仍可生成匿名演示数据）
- 每人独立设置 7 / 14 / 21 / 30 天更新周期，最长 30 天
- 管理员可代录文献、实验、算法、数据、论文、复现和项目进展；学生端保留“论文进度”和“项目进度”两个入口，其中论文按台账、阶段门、稿件版本、下一行动与导师反馈持续管理
- 进展支持一次上传最多 5 个 PDF、Office、文本、图片或 ZIP 附件；文件内容存入 R2，D1 保存归属、大小和 SHA-256 指纹，下载时再次校验学生范围
- 文献阅读需同时提交可识别论文与阅读结论
- 超级管理员、管理员（导师）、学生三级正式角色；未授权账号保持 pending
- 审核流程状态与科研判断分离：待接手、审核中、通过、补证、拒绝，以及实质性/支持性判断
- 证据来源、内容 SHA-256 指纹、审核人和不可覆盖审计轨迹
- 论文、数据集、软件、专利、报告和展示等科研成果独立台账
- 30 / 60 / 90 天黄、橙、红预警
- 飞书工作台免登、服务端会话、三级角色权限和账号绑定
- 飞书机器人进展提醒（学生绑定账号后由导师发送）
- 飞书群消息中的 AI 会议总结自动识别、去重；学生归属明确时直接拆成个人待审核进展，歧义时才人工确认
- GitHub 私有仓库只保存链接和提交号，完整代码保留给本地模型读取
- D1 持久化数据库与数据库迁移
- 学生独立个人工作台：只显示本人近期进展与导师反馈，只允许提交/补证和预约会议
- 管理端的单学生科研全景页：培养流程、下一行动、方案、节点、进展证据、成果与审计
- 会议预约状态流：学生提交/取消，管理员（导师）按分配范围处理，超级管理员全局协调

## 学生独立登录

已离开原飞书组织的学生，可以使用姓名拼音缩写（例如温浩钰 `why`、曹琛 `cc`）和密码继续访问原档案。按管理员要求，已核对原账号的 22 名普通学生统一使用初始密码 `123456789`，首次登录必须改为个人密码后才能访问业务数据。之后也可在「我的账号 → 修改登录密码」验证原密码后修改。管理员账号保留现有飞书登录。

新凭据关联原用户 ID 和学生 ID，不复制或重建历史数据。新开通的独立学生账号同样使用初始密码并强制首登改密；已开通账号忘记密码时，超级管理员可生成 24 小时有效的一次性密码设置链接。部署包含迁移 0023，以及仅执行一次的原学生账号初始化，保留已有个人密码和停用状态。操作说明见 [独立学生登录](docs/独立学生登录_2026-09-20.md)。

## 本地运行

需要 Node.js 22.13 或更高版本：

```bash
npm install
npm run dev
```

打开 `http://localhost:3000`。首次请求会在本地 D1 中创建匿名演示数据。

## 真实试用前还需配置

1. 用真实学生名单替换匿名数据，并为每人确认更新周期和当前阶段。
2. 在飞书开放平台创建企业自建应用，添加“网页应用”和“机器人”能力。
3. 网页应用主页填写 `https://progress.tz-ndt.com/`。
4. 应用身份权限至少申请“以应用的身份发消息”（`im:message:send_as_bot`）。
5. 启用会议总结导入前，申请机器人所在群消息读取、`minutes:minutes:readonly`、`minutes:minutes.artifacts:read` 和 `docx:document:readonly`；长连接订阅 `im.message.receive_v1`。无需不存在的 `im:message.history:readonly`。
6. 第一次发布时只将佘阳加入应用可用范围；完成首次登录后再逐步增加学生。
7. 将学生的飞书身份与系统学生记录绑定。
8. 对私有 GitHub 仓库安装只读 GitHub App；网站只接收元数据，本地 Agent 负责读取完整代码。

飞书密钥、GitHub 凭据和其他秘密信息不得写入仓库，应通过部署环境的加密变量配置。

### 飞书身份安全机制

- 飞书客户端通过 `requestAccess` 获取一次性授权码。
- 授权码只传给本系统服务端，服务端与飞书交换用户身份。
- 系统不保存 `user_access_token`，只保存 Open ID、姓名、角色和学生记录映射。
- 登录会话使用随机令牌，数据库只保存令牌的 SHA-256 摘要。
- 所有学生数据接口都在服务端检查角色；学生只获取本人基本信息、进展与反馈，并且只能提交/补证和预约会议；普通管理员（导师）只看显式分配学生并在 `can_review=1` 时审核，超级管理员看全部并可正式审核。
- 佘阳与于兴华均为指定超级管理员；权限只授予已核验的真实飞书账号，不按姓名或名册自动提权。
- 首位超级管理员只允许预绑定 Open ID 对应的现有管理员本人执行一次性初始化；完成后立即移除初始化变量。于兴华须先本人登录生成真实账号，再由现有超级管理员授予。
- 首位超级管理员产生后，普通管理员不能再授予或修改超级管理员；最后一名超级管理员不能被降级，高权角色变更全部写入追加式审计。
- 超级管理员不能审核由自己提交或代录的进展，也不能覆盖另一位审核人已经接手的记录。

### 群消息导入的数据边界

- 机器人仅会收到它所在群组的新消息，不会因启用事件订阅自动补录历史消息。
- 普通聊天在事件入口完成特征检查后立即丢弃，不写入数据库。
- 只有含“AI 总结”“会议总结”“会议纪要”“智能纪要”“妙记”等强特征，或同时命中多个会议结构特征的内容才会保存为候选。
- 归属明确的智能纪要会直接生成对应学生的“组会”待审核进展；归属歧义时才进入超级管理员备用区。
- 自动导入只完成归档和分配，绝不代表导师验收通过，也不会自动评分。
- 超级管理员忽略候选时会立即清除消息内容；确认导入后会清除群和发送者标识，仅保留组会文本与去重所需的消息 ID。

### 管理员删除 AI 记录

- 在“待我处理”的 AI 记录旁点击“删除”，或进入学生档案，在“AI 总结”展开记录后删除。个人进展列表也提供相同入口。
- 普通管理员仅可处理有审核权限的学生；超级管理员可管理其他学生。学生端、只读导师及账号本人绑定的学生记录不开放此操作。
- 删除后，记录不再出现在学生端、待办、AI 总结和进展统计中。进入学生档案的“AI 总结 → 已删除”可恢复。
- 原始记录、审核历史和导入关联保留，记录操作人和时间；删除当前学生的记录不会删除同一份纪要中其他学生的内容，也不会删除飞书原文。
- 数据库版本 20 增加删除标记表与并发审核保护。部署需包含迁移 0020。
